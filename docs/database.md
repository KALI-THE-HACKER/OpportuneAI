# Database Schema & Models

This document describes OpportuneAI's relational database architecture, tables, relations, indexes, migration configurations, and code repositories.

---

## 1. Table Schemas

OpportuneAI uses PostgreSQL as its primary database. Database models are defined under `backend/database/models/` using SQLAlchemy 2.0 type mapping conventions.

### 1.1 `users` Table
Stores user profiles and match preferences synced from Auth0.
- **SQL Name**: `users`
- **Columns**:

| Column Name | SQLAlchemy Type | DB Type | Constraints / Defaults | Description |
|:---|:---|:---|:---|:---|
| `id` | `Mapped[int]` | `SERIAL` | `PRIMARY KEY` | Local incremental identifier |
| `auth0_sub` | `Mapped[str]` | `VARCHAR(255)` | `UNIQUE`, `NOT NULL`, `INDEX` | Subject string from Auth0 (e.g. `auth0\|123`) |
| `email` | `Mapped[str]` | `VARCHAR(255)` | `UNIQUE`, `NOT NULL`, `INDEX` | Email address of the user |
| `name` | `Mapped[str \| None]` | `VARCHAR(255)` | `nullable=True` | Full name of the user |
| `avatar_url` | `Mapped[str \| None]` | `VARCHAR(1024)` | `nullable=True` | Avatar profile image link |
| `title` | `Mapped[str]` | `VARCHAR(255)` | `default=""` | Target professional title (e.g. Frontend Engineer) |
| `location` | `Mapped[str]` | `VARCHAR(255)` | `default=""` | Current user location |
| `bio` | `Mapped[str]` | `VARCHAR(1000)` | `default=""` | Professional biography summary |
| `years_of_experience` | `Mapped[int]` | `INTEGER` | `default=0` | Total experience years |
| `skills` | `Mapped[list[str]]` | `JSON` | `default=[]` | List of programming languages and skills |
| `preferred_roles` | `Mapped[list[str]]` | `JSON` | `default=[]` | Preferred job titles |
| `preferred_locations` | `Mapped[list[str]]` | `JSON` | `default=[]` | Target locations |
| `work_modes` | `Mapped[list[str]]` | `JSON` | `default=[]` | Allowed modes (`remote`, `hybrid`, `onsite`) |
| `min_salary` | `Mapped[int]` | `INTEGER` | `default=0` | Minimum target salary budget |
| `willing_to_relocate` | `Mapped[bool]` | `BOOLEAN` | `default=False` | Willing to relocate based on job location |
| `email_verified` | `Mapped[bool]` | `BOOLEAN` | `default=False` | Verification status from Auth0 |
| `created_at` | `Mapped[datetime]` | `TIMESTAMP` | `default=utcnow` | Registration time |
| `updated_at` | `Mapped[datetime]` | `TIMESTAMP` | `default=utcnow`, `onupdate=utcnow` | Last profile update time |

### 1.2 `raw_jobs` Table
Stores raw job postings scraped from various boards before AI processing is executed.
- **SQL Name**: `raw_jobs`
- **Columns**:

| Column Name | SQLAlchemy Type | DB Type | Constraints / Defaults | Description |
|:---|:---|:---|:---|:---|
| `id` | `Mapped[int]` | `SERIAL` | `PRIMARY KEY` | Local incremental identifier |
| `source` | `Mapped[str]` | `VARCHAR(50)` | `INDEX`, `NOT NULL` | Ingestion source platform (`linkedin`, `naukri`, etc.) |
| `external_id` | `Mapped[str \| None]` | `VARCHAR(255)` | `nullable=True` | Unique job ID assigned by the provider |
| `title` | `Mapped[str]` | `VARCHAR(500)` | `INDEX`, `NOT NULL` | Raw title of the listing |
| `company` | `Mapped[str]` | `VARCHAR(300)` | `INDEX`, `NOT NULL` | Company offering the position |
| `date_posted` | `Mapped[str \| None]` | `VARCHAR(100)` | `nullable=True` | Date string when the job was published |
| `location` | `Mapped[str \| None]` | `VARCHAR(300)` | `nullable=True` | Location where the job is based |
| `link` | `Mapped[str]` | `VARCHAR(2048)` | `NOT NULL` | Web link pointing to the original posting |
| `content_hash` | `Mapped[str]` | `VARCHAR(64)` | `UNIQUE`, `NOT NULL`, `INDEX` | Fingerprint string of (title\|company\|date\|location) |
| `raw_payload` | `Mapped[dict]` | `JSON` | `NOT NULL` | Raw JSON dictionary or scraped HTML descriptions |
| `scraped_at` | `Mapped[datetime]` | `TIMESTAMP` | `default=utcnow` | Exact scraping execution time |
| `processing_status` | `Mapped[str]` | `VARCHAR(20)` | `INDEX`, `default="pending"` | Processing state (`pending`, `processing`, `processed`, `failed`) |

### 1.3 `processed_jobs` Table
Stores the structured metadata extracted from raw job descriptions by the AI engine.
- **SQL Name**: `processed_jobs`
- **Columns**:

| Column Name | SQLAlchemy Type | DB Type | Constraints / Defaults | Description |
|:---|:---|:---|:---|:---|
| `id` | `Mapped[int]` | `SERIAL` | `PRIMARY KEY` | Local incremental identifier |
| `raw_job_id` | `Mapped[int]` | `INTEGER` | `FOREIGN KEY`, `UNIQUE`, `NOT NULL`, `INDEX` | References `raw_jobs.id` with `ondelete="CASCADE"` |
| `job_title` | `Mapped[str]` | `VARCHAR(500)` | `INDEX`, `NOT NULL` | Cleaned title generated by AI |
| `company` | `Mapped[str]` | `VARCHAR(300)` | `INDEX`, `NOT NULL` | Standardized company name |
| `skills` | `Mapped[list[str]]` | `JSON` | `NOT NULL` | Array of technical skills required |
| `location` | `Mapped[str]` | `VARCHAR(300)` | `NOT NULL` | Standardized location string |
| `salary` | `Mapped[str \| None]` | `VARCHAR(100)` | `nullable=True` | Extracted salary parameters (e.g. "$120k-$150k") |
| `experience_years` | `Mapped[int \| None]` | `INTEGER` | `nullable=True` | Extracted minimum experience years required |
| `employment_type` | `Mapped[str \| None]` | `VARCHAR(100)` | `nullable=True` | Job type (e.g. `full-time`, `contract`, `internship`) |
| `job_description` | `Mapped[str]` | `TEXT` | `NOT NULL` | Cleaned text description |
| `processed_at` | `Mapped[datetime]` | `TIMESTAMP` | `default=utcnow` | Processing completion time |

## 2. Table Relationships

```mermaid
classDiagram
    class RawJob {
        +int id
        +str source
        +str title
        +str content_hash
        +str processing_status
    }
    class ProcessedJob {
        +int id
        +int raw_job_id
        +str job_title
        +list skills
        +str job_description
    }
    RawJob "1" -- "0..1" ProcessedJob : Back-populates (raw_job_id / 1:1)
```

- **1-to-1 Association**: `RawJob` has a 1-to-1 relationship with `ProcessedJob` mapped via `raw_job_id`. 
- **Cascade Purges**: Deleting a row from `raw_jobs` automatically triggers a cascading purge of its associated `processed_jobs` row, preventing orphaned records.

## 3. Migration Strategy (Alembic)

OpportuneAI manages database schema versions incrementally via Alembic.

### Execution Workflow
1. **Create Migrations**: Generated automatically using `alembic revision --autogenerate -m "description"` by comparing SQLAlchemy model definitions with the active database.
2. **Database Engine**: Since Alembic's default wrappers are synchronous, it uses `ALEMBIC_DATABASE_URL` (standard `postgresql://` protocol) to run migrations, while FastAPI app sessions use `DATABASE_URL` with the asynchronous `postgresql+asyncpg://` protocol.
3. **Upgrade Commands**: Running `alembic upgrade head` applies all pending migrations in order.

## 4. Key Repositories & SQL Construction

Data access operations are isolated inside repository classes under `backend/database/repositories/`.

### 4.1 Ingestion Deduplication Query
Used by the pipeline to fetch all existing fingerprints and avoid re-inserting duplicates:
```python
# From database/repositories/raw_job_repository.py
result = await self.db.execute(select(RawJob.content_hash))
existing_hashes = set(result.scalars().all())
```

### 4.2 Status Transition Update
Updates the processing status of a raw job during worker execution:
```python
# From workers/ai_worker.py
raw_job = await db.get(RawJob, raw_job_id)
raw_job.processing_status = ProcessingStatus.PROCESSING
await db.commit()
```

### 4.3 Profile Synchronization
Verifies if an authenticated Auth0 user has a local profile cached:
```python
# From database/repositories/user_repository.py
result = await self.db.execute(select(User).where(User.auth0_sub == auth0_sub))
user = result.scalar_one_or_none()
```
If missing, a new row is created; if found, fields like email verification status and avatars are synchronized.
